# 雷神控制中心 · 重建版（LeishenCC）

从零复刻的雷神（Leishen）笔记本控制中心桌面程序，Windows 11 原生风格 WPF 实现。

原厂 `ControlCenter` 的硬件控制协议通过逆向分析还原，本仓库只包含**自行编写的代码**，不含任何第三方程序的反编译产物。

---

## 特性

| 页面 | 功能 |
| --- | --- |
| 概览 | CPU/GPU/内存实时指标、当前状态汇总、可选指标的历史趋势折线图（1/3/5 分钟） |
| 性能模式 | 高性能 / 游戏 / 办公静音切换，可联动 Windows 电源计划 |
| 风扇与散热 | 3 档位 × CPU/GPU/系统 三路风扇曲线编辑，可拖动折点；**常驻每 2 秒按曲线下发，与窗口是否可见无关** |
| 键盘灯效 | 4 套灯效档案 × 5 个灯区，模式/亮度/RGB 与预设色 |
| 显卡与显示 | 混合输出 / 独显直连 / 核显切换，HSR 刷新率切换 |
| 系统设置 | **开机自启（计划任务替代原厂）**、Win 键屏蔽、摄像头启停、Fn 组合键监听、托盘与主题 |
| 接口诊断 | 原始 SMI 命令收发（a0–a6 十六进制输入）与调用日志 |

- **Fn 组合键监听**：复刻原厂守护进程行为，监听 `root\wmi:GMC_WMIEvent`，响应性能模式键、控制中心键、摄像头键与背光键。
- **界面**：Fluent / OpenFRP 风格的侧边栏（主区菜单 + 底区分页），可收起为仅图标；页面切换淡入动效；沉浸式无边框标题栏与覆盖式细滚动条；深浅双主题。

### 接口能力实测

以下为 `0xFA00` 查询的实机快照（接电状态）：

| 查询 | 返回 | 含义 |
| --- | --- | --- |
| `0x0201` 能力 | a0=`0x0200`、a2=`52` | SMI 版本 512；SKU 52 → 三风扇 + 自定义风扇可用 |
| `0x0202` 硬件状态 | a3=`1`、a4=`1`、a5=`1`、a6=`1` | 适配器已接、摄像头状态 1；`a4==2` 判定 HSR、`a6==2` 判定 DDS |

## 硬件控制协议

通道：`root\wmi` 命名空间下的 `RW_GMWMI`，通过 32 字节 `BufferBytes` 读写，即原厂 `MyWmiBase.ACPIPerformSMI`。

结构体（小端）：`a0(2) a1(2) a2(4) a3(4) a4(4) a5(4) a6(4) rev0(4) rev1(4)`。
方向位：`a0 = 0xFA00`（GET，64000）/ `0xFB00`（SET，64256）。

### GET (`0xFA00`)

| a1 | 含义 | 返回 |
| --- | --- | --- |
| `0x0100` | LED 状态 | — |
| `0x0200` | 温度与转速 | a2=CPU 温度 a3=GPU 温度 a4=CPU 转速 a5=GPU 转速 |
| `0x0201` | 能力查询 | a0=SMI 版本 a2=SKU |
| `0x0202` | 硬件状态 | a3=适配器 a4=HSR(==2) a5=摄像头 a6=DDS(==2) |
| `0x0203` | 显示状态 | a2=当前 a3=HDMI a4=初始 |
| `0x0204` | HSR | — |
| `0x0205` | 风扇默认表 ID | — |
| `0x0206` | 自定义风扇状态 | a2=1 开启 |
| `0x0207` | 系统温度/风扇 | a2=温度 a3=转速 |

### SET (`0xFB00`)

| a1 | 含义 | 参数 |
| --- | --- | --- |
| `0x0100` | LED 设置 | a2=灯区 a3=LED 数据 |
| `0x0200` | Win 键 | a6=1 屏蔽 a6=0 恢复 |
| `0x0203` | 显示模式 | a2: 1=混合 2=独显 3=UMA |
| `0x0204` | HSR | a2=档位 |
| `0x0205` | 风扇转速 | a2=CPU% a3=GPU% a4=SYS% |
| `0x0206` | 风扇控制开关 | a2=1/0 |
| `0x0300` | 性能模式 | a2: 0=高性能 1=游戏 2=办公 |
| `0x0400` | 事件清除 | a2=性能键 a3=控制中心键 a4=摄像头键 |

### LED 数据位域

```
bit31..28  模式（0 关闭 / 1 常亮 / 3 呼吸 / 6 彩色循环 / 7 氛围灯）
bit27..24  亮度 0-15
bit23..16  R
bit15..8   G
bit7..0    B
```
灯区：5=键盘区1、4=键盘区2、3=键盘区3、8=LOGO、7=尾部灯带。

### Fn 组合键事件

事件类 `root\wmi:GMC_WMIEvent`，负载 `EventDetail` 为 32 字节：

| 字节 | 含义 |
| --- | --- |
| `[0]` | 键盘背光亮度（0-15） |
| `[4]` | ==1 外接显示事件 |
| `[5]` | ==159 电源适配器事件 |
| `[6]` | 摄像头（1=开 / 2=关） |
| `[7]` | 性能模式键 |
| `[8]` | 控制中心键 |

处理完必须下发 `0xFB00/0x0400` 清事件，否则 EC 会一直挂起该事件。

**实测按键映射（2026-10-19 21:51 带标签抓包确认）**：

| 键 | 事件流与特征 | 含义 | 程序行为 |
| --- | --- | --- | --- |
| `Fn+1` | **WMI2Event `0x30`**（`data=b[30]`：>0=max / 0=normal；OSD 显示 `MAX`），GMC 流没有它 | 风扇 max 开关（强冷） | 按状态幂等应用三路 100% / 撤销：回到自定义曲线，没开自定义风扇则 `0x0206=0` + `0x0205=FF/FF/FF` 交还 BIOS |
| `Fn+2` | `b[0]=亮度`，其余全 0（`0` 即关灯） | 键盘背光 | 写 LED 三个分区亮度 |
| `Fn+3` | **GMC `b[7]=1`、`b[1]=0x07`**（无 WMI2 事件、OSD 无图标） | 性能模式 / 电源方案 | 模式循环 `0→2→1→0` + Windows 电源计划 + 风扇档位联动 |

> 早期按 `b[1]` 键码区分 Fn+1/Fn+3 是错的：Fn+3 的键码同样是 `0x07`。实测两条流是**互斥**的——
> Fn+1 只出 WMI2、Fn+3 只出 GMC，因此不需要键码判据，也不需要跨流去重。

EC 对**同一次按键**会连发两条相同负载（实测背光键双发间隔 190–375ms；性能键也见过 26ms/212ms/225ms）。去重算法见下一节：短窗 600ms 判回声，600–2500ms 灰区执行并告警，不再用旧版 2500ms 一刀切（会吞真实按键）。

强冷（Fn+1 或风扇页按钮）最长持续 20 分钟，超时自动撤销并交还 BIOS：EC 偶尔会停掉性能键上报（实测重启后第一次按键正常、随后静默），这时按第二下收不回来，靠超时兜底。

性能模式键按原厂顺序循环：`0(高性能) → 2(办公) → 1(游戏) → 0`，与原厂 `ParseWMIEventData` 一致。

**模式切换必须联动风扇档位。** 自定义风扇运行时，本程序每 2 秒按「当前档位」重写一次占空比（`0xFB00/0x0205`），
EC 自己的模式风扇表会被直接覆盖；如果切模式时不动档位，用户看到的就是「按 Fn 键没反应」。
因此 `PowerModeService.Apply` 统一下发：SMI → 模式状态 → Windows 电源计划（可选）→ 风扇档位换到同一档并立即重算，
Fn 键与性能页走同一条路径。

### Fn 监听通道与健壮性（2026-10-19 完善）

**通道结论（含 Ghidra 逆向证据，详见 `analysis/`）**

- `GMC_WMIEvent` 由 BIOS 的 ACPI WMI mapper（`ACPI\PNP0C14` → `wmiacpi.sys`）提供，负载 32 字节 `EventDetail`。
- 原厂 `ControlCenter64.sys`（Quanta，设备 `\Device\CCDRV1`）与 Fn 热键**无关**：它在本机因签名校验失败
  未加载（系统日志 7000），而原厂控制中心在驱动未加载时 Fn 键依然正常。Fn 监听只依赖 root\wmi。
- 机器上还装有厂商 **Hotkey OSD 1.4.40TPN2**（`C:\Program Files\Hotkey OSD\`，`hkosdservice` 常驻）。
  它订阅的是 **`WMI2Event`**（标准 ACPI 事件 GUID `{ABBC0F20-8EA1-11D1-00A0-C90629100000}`），
  与本机 BIOS 私有 `GMC_WMIEvent`（GUID `{74286D6E-429C-427a-B34B-B5D15D032B05}`）是**两路独立事件流**，
  编码也不同：`WMI2Event` 的 `b[0]` 是事件 ID（0x0D/0x30/0x33/0x34/0x35/0x39），数据字节位置按事件 ID 查表；
  `GMC_WMIEvent` 才是上面那张 `[0]/[4]/[5]/[6]/[7]/[8]` 表。
  两路 GUID 不同、互不覆盖，**要同时订阅**；`WMI2Event` 流不需要 `0xFB00/0x0400` 确认（OSD 自己也不发）。
- 现在主程序双路监听：`GMC_WMIEvent` 走原有动作；`WMI2Event` 负责 OSD 才有的键。
  其中 **`0x30` 风扇键直接接管 Fn+1**（见下一节），其余 `0x0D/0x33/0x34/0x35/0x39` 暂时只解码记录
  （事件 ID→风扇/触摸板/FnLock/麦克风/使用模式的映射还在实机标注，先保证"按了键能看到日志/历史"），
  不会执行未经验证的硬件动作。`--fnprobe` 同时输出 `[GMC]` 与 `[WMI2]` 两路原始 32 字节。
- 逆向证据：`analysis/ghidra-driver-report.md`（ControlCenter64.sys / C64.dll）、
  `analysis/hotkey-osd-report.md`（WMI2Event 解析表）、`analysis/fn-gap-analysis.md`（原厂 Fn 语义逐行对比）。

**Fn+1 / Fn+3 标定（2026-10-19 21:51，带标签 `--fnprobe 90`）**

| 按键 | GMC 流 | WMI2 流 | 结论 |
| --- | --- | --- | --- |
| Fn+3 ×3（间隔 5s） | 3 条 `02 07 … 01`（`b[7]=1`、键码 `0x07`） | **0 条** | Fn+3 = GMC 性能键；OSD 无图标 |
| Fn+1 ×3（间隔 5s） | 0 条 | 4 条 `0x30`，data `1→0→1→0` | Fn+1 = WMI2 风扇状态键；OSD 显示 `MAX` |
| Fn+2 ×1 | 2 条背光（29ms 双发） | 0 条 | 背光只走 GMC |

→ **Fn+1 只走 WMI2、Fn+3 只走 GMC（互斥）**。因此：
- Fn+1 由 `FanControlService.SetBoost(bool)` 按 data **幂等应用**强冷状态（不是 toggle）；
- Fn+3 由 `HandlePerformanceKey` 一律按原厂语义切性能模式（不再看 `b[1]` 键码——Fn+3 的键码同样是 `0x07`，旧实现会把它误当强冷）；
- 不需要跨流去重：两个键不会在同一事件里同时出现。

另有一次 21:04 的 180s 抓包（当次全按 Fn+1）里 GMC 流 0 条、WMI2 0x30 60+ 条，说明 **EC 停报 GMC 性能键时 Fn+1 依然可用**；
而 Fn+3 在那种状态下确实无事件可接（只能等 EC 恢复或重启）。

**真机验证（2026-10-19 21:40–21:44）**：`data=1` → `强冷开启：三路 100%（临时接管）`，风扇持续 100%、松开不回退
（证明 data 是"风扇状态"而不是"按键按下/抬起"）；`data=0` → 撤销；原厂 Hotkey OSD 在按下时显示 `MAX` 图标。
同一轮里开启自定义风扇后，`data=0` 正确回到自定义曲线。

**最终真机验证（2026-10-19 22:13，修复后）**

```text

22:13:51  性能模式[Fn+3]: 办公/静音 → 游戏（SMI=成功，电源计划=已切换，风扇档位 → 2，已按新曲线下发）

22:13:56  WMI2 风扇键: data=0 → 强冷关闭（Fn+1 风扇键），回到自定义曲线
```

- Fn+3 三档循环、电源计划与风扇档位联动全部生效；
- Fn+1 在「自定义曲线运行中」与「未开自定义风扇」两种情况下都能正确撤销（分别回曲线/交还 BIOS）；
- 背光键、摄像头键、控制中心键沿用原有链路。

**撤销后必须写 `0x0205 = 255/255/255`**：实测只发 `0x0206=0` 时 EC 会保留最后一次 100% 占空比，风扇不回 BIOS。
原厂 `DisableUserDefineFan` 的顺序就是 `SetFanControlStatus(0)` → `SetFanSpeedWMI(255,255,255)`，
现在 `ReleaseToBios()` 照抄这个顺序，关闭自定义风扇/撤销强冷/程序退出/连续失败交回都走它。

**去重：短窗 + 灰区执行，不再吞真实按键**

- 实测背光键 13/13 次按键都是双发、间隔 **190–375ms**（中位 253ms）——这是可靠的"EC 回声"标尺。
- 旧版 2500ms 窗口会把 1~2 秒后的真实第二次按键当回声吞掉（日志可复现：20:20 的 13 条事件只执行 6 条）。
- 现算法：**全 32 字节相同 + 间隔 ≤ 600ms** → 判回声丢弃；相同但间隔 600–2500ms（灰区）→ **执行并记 WARN**
  （无法区分延迟回声与真实按键；吞按键无反馈，误执行一次用户可再按一次纠正）；
  任何非性能键事件到达时重置回声状态。窗口可用 `HKCU\SOFTWARE\LeishenCC\FnEchoWindowMs` 调整（100–2500）。

**事件确认（0xFB00/0x0400）**

- 处理完在 `finally` 里确认，处理抛异常也确认；确认失败重试一次并记录返回值；
  连续 3 次失败自动重建订阅。
- 启动成功后、系统从睡眠唤醒后，顺序清 2/3/4 三个事件位（原厂每次只写一个字段，所以这里也是 3 条单字段 SMI），
  清除历史残位。未识别事件也会按 2/3/4 全量兜底清一次。
- 界面「系统设置 → 监听 Fn 组合键」有「重新订阅」「清事件位」按钮和最近 8 条事件历史
  （含间隔、回声判定、动作、确认结果），不必重启程序就能排查。

**原厂语义对齐**

- Fn+3 在**电池供电**或 **Type-C 适配器供电**时只记录事件、不切模式/电源计划（原厂 `!IsOnDCMode && !IsTypeCAdapterIn`）；
  事件确认照发。Fn+1 强冷是自定义功能，不受该门控限制。
- HDMI 事件只重读显示状态，**不自动切回混合模式**（原厂会 `SetHybridMode`；从热键自动切显卡风险过高，有意不复刻）。
- 原厂 `Event_Alpha` 门控是"背光快照一致性校验"，不是去重；daemon 版会吞启动后首条非背光事件。
  本实现用"全 32 字节比较"达到同样目的，不吞首条事件。

**SMI 流量（与 EC 共享通道）**

- EC 温度/转速改为 **2.5s** 一次（界面 1s 刷新复用缓存），SYS 温度/转速 **10s** 一次；
  风扇服务复用同一缓存、不再自己读 EC；占空比"变化才写"，保活从 30s 延长到 **300s**。
- 稳态 SMI 从约 3.6 次/秒降到约 1 次/秒（原厂 daemon 约 0.4 次/秒）；`--fnprobe` 模式会停掉所有周期轮询，
  避免抓包期间自己干扰热键事件。
- 仍未能定案的历史问题：性能键偶发彻底停报（EC 侧闩锁 vs SMI 高频饿死 EC 热键任务），
  现已有"确认可观测 + 自动重建 + 清残位"兜底；用 `--fnprobe` 做标注实验可继续定位。

**`--fnprobe` 抓包实验**（管理员运行）：

| 组 | 操作 | 目的 |
| --- | --- | --- |
| A | 单按 20 次，间隔 ≥3s | 确认一次按压产生几条事件、回声间隔上界 |
| B | 每次连按 2 下、间隔 ~1s，共 10 组 | 检查灰区（600–2500ms）是否把真实第二下误判 |
| C | 每次连按 2 下、间隔 ~2s，共 10 组 | 同上，验证 >2.5s 不再判回声 |

日志 `fnprobe.log` 会写全 32 字节、间隔、回声/按键判定、动作与确认结果；A 组回声上界 × 1.5 即为建议窗口。

抓包模式现在是**只读**：`FnKeyService.DryRun=true`，只解析/记录/确认，不写背光、不动摄像头、不强冷、不切模式、不拉窗口；
并且会先检查 `Local\LeishenCC.App`，如果已有托盘实例在运行就直接退出——两个实例同时订阅会抢事件、
抢 `Local\LeishenFanOwner` 风扇所有权（实测日志出现「风扇已被外部进程接管」和同一按键被处理两次）。
抓包前请先完全退出控制中心（含托盘）。

### 风扇曲线

8 个温度断点 `30/40/50/60/70/80/90/100 ℃`，注册表中存为 `30,30,30,30,50,60,70,100` 形式的逗号串，双风扇用 `;` 分隔 CPU/GPU，系统风扇单独存 `UserFan*_SYS`。

### 注册表

与原厂共用 `HKLM\SOFTWARE\WOW6432Node\LeiShen\ControlCenter`（`Game`/`HighPerformance`/`PowerSaving`/`Custom`/`LEDModule`/`WinKey`/`FanControlStatus`/`FanControlSelect`/`UserFan*`）；本程序自身的界面偏好存 `HKCU\SOFTWARE\LeishenCC`。

性能模式状态存 **`ModeBeforeDC`**：原厂 `REG_MAIN.POWERPLAN`(=11) 在 `GetRegistry(byte)` 的 switch 里映射到的就是这个名字，
性能键切换时也写它。读模式时优先读这里，缺失才回退到本程序的 `HKCU\SOFTWARE\LeishenCC\PowerMode`（旧版本遗留键）。

风扇档位（`FanControlSelect` 0/1/2）与性能模式一一对应：**1=高性能、2=游戏、3=办公**，原厂三套默认曲线的激进程度也是这个顺序。

## MCP 服务（可选，仅本地）

`tools/FanMcp` 提供一个 stdio 传输的 MCP 服务，让本地 agent 直接读写自定义风扇曲线。

- **仅本地可达**：使用 stdio，不监听任何端口，只能由 MCP 客户端以子进程方式拉起，不存在对外暴露面。
- **复用同一份源码**：直接链接 `src/LeishenCC/Core` 下的 `GmWmi` / `FanProfile` / `Settings` / `SystemStats`，与界面行为一致（每 2 秒按「曲线 + 当前温度」下发）。
- **安全兜底**：进程退出（含 stdin EOF）时，只有本进程接管过风扇才会自动下发 `0xFB00/0x0206` 交回 BIOS；从未接管则不触碰当前状态。

### 工具

| 工具 | 作用 |
| --- | --- |
| `fan_status` | 控制开关、三路温度/转速、曲线目标占空比、最近下发结果（只读） |
| `fan_list_profiles` | 三档曲线与当前档位（只读） |
| `fan_set_curve` | 写入某档曲线（仅注册表，8 点对应 30–100℃） |
| `fan_apply_slot` | 启用某档并接管，按曲线持续下发 |
| `fan_set_speed` | 立即下发固定占空比（不随温度变化） |
| `fan_stop` | 关闭自定义控制，交回 BIOS |
| `fan_reset_curve` | 恢复该机型默认曲线（按风扇表编号） |
| `ec_read` | 只读诊断查询（`0xFA00`，返回 a0/a2..a6） |

### 构建与接入

```bash
cd tools/FanMcp
dotnet build -c Release
```

MCP 客户端配置（`mcpServers` 格式）：

```json
{
  "mcpServers": {
    "leishen-fan": {
      "command": "C:/Users/<you>/Documents/LeishenReverse/tools/FanMcp/bin/Release/net5.0-windows/LeishenFanMcp.exe",
      "args": []
    }
  }
}
```

自检：`python tools/FanMcp/probe.py` —— 走一遍握手、列工具、读曲线，并把曲线**原样写回**，不改变实际风扇行为。

> 桌面端与本服务通过命名互斥量 `Local\LeishenFanOwner` 互斥：只要 LeishenCC 开着自定义风扇，外部 `--hold` 会直接退出；反之桌面端会让位。

## 状态刷新机制

- 1 秒快刷新：温度 / 占用 / 转速，并写入采样历史。
- 5 秒慢刷新：重读显示输出、风扇控制、摄像头与性能模式，与上次快照比对，变化才刷新界面（对应原厂 `timer2` 5 秒 tick）。
- 切页、从托盘恢复、Fn 键切换模式时立即补一次刷新。
- 页面事件订阅采用 `Loaded`/`Unloaded` 成对方式，切页回来后不会停止刷新。

## 风扇常驻下发（`Core/FanControlService`）

原实现的下发写在 `FanView.OnUpdated` 里，而该订阅随页面 `Unloaded` 取消——打游戏时窗口在托盘、页面不在可视树，**下发会停止**，EC 就锁在最后一次的占空比上（实测：50 分钟游戏转速恒定 2886 RPM，CPU 卡在 82℃ 温度墙而风扇只有 ~65%）。

现在改为独立服务：

- 用 `System.Threading.Timer` 每 2 秒下发，**与页面可见性无关**，只要 LeishenCC 在运行（含托盘）就持续生效。
- 取档带 **2℃ 滞回**：升温立即升档，降档需低于当前档下界 2℃，避免原厂 10℃ 阶梯在断点附近抖动（实测 2630↔3617 RPM 来回跳）。
- 连续 5 次下发失败自动交回 BIOS，不会锁死在错误占空比。
- **程序退出时自动 `SetFanControl(false)` 交回 BIOS**，避免把风扇锁在最后的设定值。
- 与外部 `LeishenFanMcp --hold` 用 `Local\LeishenFanOwner` 互斥，谁先接管谁生效。

## 开机自启：替代原厂控制中心（`Core/StartupTask`）

原厂的登录自启不是 Run 键，而是一个计划任务：

```
\ControlCenter\ControlCenter  →  ControlCenterDaemon.exe /1
                                LogonTrigger · RunLevel=HighestAvailable
```

重置版沿用同一机制（`系统设置 → 开机自启`）：

- **接管**：注册 `\LeishenCC` 计划任务（登录触发、`HighestAvailable`、延迟 8 秒、带 `--startup` 参数），并把原厂任务 `Enabled=false`。
- **取消**：删除 `\LeishenCC`，把原厂任务恢复为启用。所有操作可逆，原任务定义另外备份在 `backup/ControlCenter.task.xml`。

为什么不用 `HKCU\...\Run`：本程序是 `requireAdministrator` 清单，走 Run 键每次登录都会弹一次 UAC；计划任务用 `HighestAvailable + InteractiveToken`，登录时静默提权，不弹窗。旧版本写过的 Run 键会在接管/取消时自动清掉。

启动参数：

| 参数 | 行为 |
|---|---|
| `--startup` | 不显示主窗口，直接驻留托盘（计划任务使用），并弹一次托盘提示 |
| `--startup-enable` / `--startup-disable` | 不建窗口，直接接管 / 恢复开机自启，结果写 `startup.log` 后退出（便于脚本化） |
| （无参数） | 正常显示窗口 |

配套细节：

- **单实例**：`Local\LeishenCC.App` 互斥量；重复启动会通过命名事件 `Local\LeishenCC.Show` 让已有实例把窗口显示出来，而不是开出第二个托盘图标。
- **路径自愈**：程序被移动或重新构建后，若任务里记录的 exe 路径与当前不一致，启动时自动按当前路径重新注册。
- **状态三态**：任务状态分「启用 / 禁用 / 不存在 / 读不到」；非管理员读不到 `\ControlCenter\` 文件夹时会如实提示，不会误判成「未启用」。
- 自检：`tools/StartupProbe`（编译后运行，输出 `startupprobe.log`；`--enable` / `--disable` 可直接执行接管/恢复）。

## SYS 风扇（吹南桥）实测与曲线依据

SYS 这一路吹的是南桥（PCH），`0xFA00/0x0207` 读到的 SYS 温度就是它的温度。用 `tools/FanSweep` 做过一次隔离扫频（固定 CPU 75% / GPU 45%，只改 SYS，每档稳定 90s + 采样 45s）：

| SYS 占空比 | SYS 转速 | 南桥温度 | GPU 温度 |
|---|---|---|---|
| 20% | 1201 | 55℃ | 55℃ |
| 40% | 2398 | 53℃ | 53℃ |
| 60% | 3605 | 52℃ | 52℃ |
| 80% | 4802 | 51℃ | 51℃ |
| 100% | 6006 | 50℃ | 50℃ |

结论：

- 转速与占空比近似线性，**约 60 RPM / 1%**（20%→1201，100%→6006）。
- 全量 1200→6006 转只换 **5℃**；第一段 1200 转换 2℃，之后每 1200 转只换 1℃。
- 所以原曲线（80℃→85%、90℃→100%，游戏中冲到 5796 RPM）对南桥是过度投入，且它是整机最吵的一路。
- SYS 风扇同时影响 GPU（同样约 5℃），所以不能砍到最低，保留基础气流更划算。

按此把两档 SYS 曲线改为「低段保基础气流、高温段不过度堆转速」：

| 档位 | 旧 SYS 曲线 | 新 SYS 曲线 |
|---|---|---|
| 1 性能 | 20,25,35,50,70,85,100,100 | 22,22,26,32,42,55,70,92 |
| 2 平衡 | 20,25,32,42,50,70,82,92 | 20,20,23,28,36,46,58,78 |
| 3 原厂 | 30,30,30,30,50,60,70,100 | 未改动 |

实测效果：南桥 52℃ 时 SYS 从 1916–2495 转降到约 **1400 转**；同时 60℃ 断点的转速跳变（1916↔2495）随之消失。
